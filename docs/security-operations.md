# 安全运维

## 上线前检查

1. 启用 `AUTH_MODE=enabled` 并轮换初始管理员密码；
2. 使用至少 32 字符随机 JWT 密钥并放入密钥管理服务；
3. 使用 PostgreSQL 和受控 S3，对数据库、对象和备份加密；
4. 保持 `ALLOW_EXTERNAL_MODEL_FOR_CASE_FILES=false`，直至完成授权及供应商评估；
5. 核对模型服务的数据留存、训练使用、地区和分包商条款；
6. 为上传入口增加组织认可的恶意文件扫描服务；
7. 配置 TLS、安全响应头、访问日志留存和异常告警；
8. 执行备份恢复、账号停用和数据删除演练。

## 权限矩阵

- viewer：只读；
- assistant：材料处理和 Agent 执行；
- lawyer：案件修改、人工复核和知识维护；
- admin：成员、角色及工作空间管理。

后端权限检查是最终边界，前端隐藏按钮不作为安全控制。

## 模型数据边界

案件材料默认不发送给外部模型。显式授权后，系统会先遮盖常见身份证号、手机号、邮箱和银行卡号。脱敏不是匿名化保证；律师仍须确认材料是否允许发送。

模型抽取结果必须包含 `document_id + quote`。引用无法在输入材料中验证时拒绝入库。疑似 Prompt Injection 只作为材料文本保存，并进入人工检查。

## 事件响应

发生疑似泄露时应立即关闭外部模型授权、停用相关账号、轮换模型/JWT/S3 密钥、保全请求 ID 和审计日志，并依据组织制度通知负责人。仓库不替代正式事件响应制度。
