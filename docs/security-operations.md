# 安全运维

## 上线前检查

1. 启用 `AUTH_MODE=enabled` 并轮换初始管理员密码；
2. 使用至少 32 字符随机 JWT 密钥并放入密钥管理服务；
3. 使用 PostgreSQL 和受控 S3，对数据库、对象和备份加密；
4. 保持 `ALLOW_EXTERNAL_MODEL_FOR_CASE_FILES=false`，直至完成授权及供应商评估；
5. 核对模型服务的数据留存、训练使用、地区和分包商条款；
6. 启用并监控仓库已接入的 ClamAV；验证扫描不可用时上传会被拒绝；
7. 配置 TLS、安全响应头、访问日志留存和异常告警；
8. 执行备份恢复、账号停用和数据删除演练。
9. 以管理员身份检查 `/api/system/readiness`，关闭全部 fail 项并处置 warn 项；
10. 使用固定版本或 digest 的 PostgreSQL、MinIO 和 ClamAV 镜像。

## 权限矩阵

- viewer：只读；
- assistant：材料处理和 Agent 执行；
- lawyer：案件修改、人工复核和知识维护；
- admin：成员、角色及工作空间管理。

后端权限检查是最终边界，前端隐藏按钮不作为安全控制。

## 前端依赖审计说明

2026-07-26 的复核发现 React Router 7.18.1 新增一项 RSC Mode CSRF 高危公告。项目已迁移到 `react-router` 8.3.0（v8 不再需要 `react-router-dom`），并完成 TypeScript/Vite 构建；`npm audit --omit=dev` 当前为 0 项。仍应在每次发布时重新执行依赖审计，不能把单次结果视为长期安全保证。

## 模型数据边界

案件材料默认不发送给外部模型。显式授权后，系统会先遮盖常见身份证号、手机号、邮箱和银行卡号。脱敏不是匿名化保证；律师仍须确认材料是否允许发送。

模型抽取结果必须包含 `document_id + quote`。引用无法在输入材料中验证时拒绝入库。疑似 Prompt Injection 只作为材料文本保存，并进入人工检查。

## 规则供应链

YAML 规则加载前会校验版本、稳定 ID、严重级别、输出类型和强制复核标志。启用个人经验规则还必须填写负责人、适用地区、复核日期和来源标题。规则变更应经过律师复核、代码审查和回归评测，不应直接在生产容器内修改。

## 数据删除演练

先执行 `python -m services.data_retention` 查看候选项，核对备份、案件状态和保留义务后，再使用带确认短语的执行命令。删除结果应留存在受控运维日志中；对象存储删除失败的案件不会删除数据库记录。

## 事件响应

发生疑似泄露时应立即关闭外部模型授权、停用相关账号、轮换模型/JWT/S3 密钥、保全请求 ID 和审计日志，并依据组织制度通知负责人。仓库不替代正式事件响应制度。
