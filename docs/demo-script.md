# 三分钟 Demo 脚本

## 目标

让面试官在三分钟内看到：这不是法律问答机器人，而是围绕具体案件运行、能够追溯材料并要求律师复核的工作空间。

## 0:00–0:25｜案件工作台

打开首页，说明：

> 系统以案件为单位保存材料、事实、证据和复核记录。两个案例均完全虚构，合同案例展示通用能力，交通事故案例展示领域插件。

指出首页的事实来源覆盖、赔偿项目矩阵和工作流节点指标。

## 0:25–0:55｜交通事故专业模块

进入“交通事故人伤专业演示案”，打开“交通专业分析”。

说明：

> 通用流程完成材料解析和事实提取后，Domain Router 加载交通事故插件，进一步整理事故责任、伤情治疗、医疗费用和赔偿项目证据。

## 0:55–1:25｜冲突与缺失材料

展示住院日期与票据日期冲突，以及护理证明缺失。

说明：

> 系统只提示冲突和材料缺口，不自动判断费用合理性、因果关系或护理期限。

## 1:25–1:55｜材料来源

在事实或风险项中点击“定位到原文”，展示文件名、页码和高亮片段。

说明：

> 每条当前事实都必须绑定材料来源；近似定位会提示律师再次核对。

## 1:55–2:20｜Agent 执行过程

打开“Agent 执行”，展示节点状态、输入输出摘要、警告和单节点重跑。

说明：

> 节点是一个可观察工作流中的结构化功能，不是多个 Agent 自由对话。

## 2:20–2:45｜律师人工复核

打开“律师复核”，展示接受、修改、驳回和历史记录。

说明：

> AI 提取事实、模型建议和律师确认结论在数据层严格区分，高风险项必须人工处理。

## 2:45–3:00｜辅助报告

打开报告中心，展示引用目录和免责声明。

结束语：

> 项目证明的是 Agent 产品设计、领域规则工程化和可信 AI 工作流，不宣称替代律师或自动形成法律结论。

## 演示前检查

```powershell
start-demo.cmd
```

- 首页显示两个虚构案例；
- 交通事故案例存在冲突、缺失材料和强制人工复核项；
- 所有关键页面可打开；
- 不启用真实客户材料；
- 不依赖模型 API Key。
