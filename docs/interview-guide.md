# 面试讲解指南

## 30 秒项目介绍

> Lawyer Case Copilot 是面向案件负责律师的可追溯办案工作空间。它先提供所有民事案件共用的材料、事实、时间线、证据和人工复核能力，再通过可插拔领域模块处理交通事故人伤的治疗过程、医疗费用、赔偿项目和证据完整性。系统默认不形成确定法律结论，每条关键输出都绑定材料来源并进入律师复核。

## 建议重点讲述

1. 从法律问答转向案件工作空间的产品判断；
2. 通用能力与专业领域插件的架构拆分；
3. Workflow Orchestrator 而不是复杂 Multi-Agent；
4. 来源引用、无依据输出拦截和 Human Review；
5. 个人办案经验如何转换为可配置、可测试的规则；
6. 完全虚构评测集如何避免不真实的业务效果声明。

## 常见追问

### 为什么不直接让大模型阅读全部材料？

长上下文不能替代材料解析、页级引用、冲突保存和复核状态。结构化工作流还能局部重跑、测试和审计。

### 这与 RAG 法律问答有什么区别？

RAG 只负责知识检索的一部分。本项目的主线是具体案件状态：材料、事实、时间线、证据、任务、风险和律师确认。

### 为什么不用 Multi-Agent？

节点间不存在需要自由协商的角色关系。结构化节点更可控、更低成本，也更符合可追溯要求。

### 如何防止模型幻觉？

使用结构化 Schema、材料引用校验、无依据输出拒绝、冲突不自动合并、知识来源元数据和律师人工复核。

### 如何证明有效？

当前只能证明虚构场景下的结构完整性和可追溯性。真实准确率需要经过授权、脱敏并由律师标注的数据集，仓库不虚构该结果。

### 下一步最重要的是什么？

不是增加更多案件类型，而是把项目所有者的真实办案经验转化为有来源、有适用范围、有版本和回归测试的规则。
